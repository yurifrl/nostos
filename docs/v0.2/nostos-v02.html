nostos v0.2 — Provisioner Architecture & Session Log

Session-grade reference. Sources cited inline. Generated 2026-05-25.

nostos v0.1 shipped a single boot method (PXE, x86-only). v0.2 introduces a Provisioner abstraction so that the same command — nostos node install <name> — drives any boot method: PXE for the Dell controlplane, BMC flashing for Turing Pi RK1 modules, and (in v0.3+) Redfish, Proxmox, USB, rpi-imager. The session captured here ends with dell01, tp1, and tp4 all Ready in the Kubernetes cluster and joined to Tailscale, with rendered machineconfigs minted with fresh OAuth-derived authkeys per render and the legacy taskfiles/turing.yml flow retired.

Boot methods: pxe, tpi 3/3 nodes Ready 89 unit tests / 18 packages PR not merged at write time

This document is exhaustive on purpose. The user explicitly asked for thoroughness on every architecture decision and every CLI use case. Source citations point at specific files in .submodules/nostos/ and openspec/changes/nostos-v02-provisioners/. Items in the design that did not ship are explicitly marked DEFERRED v0.3 or later.

2. Real-world run timeline

Each step lists the command, the observed outcome, and what changed (code, config, or 1Password) to unblock it. The full lifecycle: started with nostos node install tp4 failing on a missing image digest pin and ended with three nodes Ready on the cluster.

Step 1 — First attempt: nostos node install tp4

$ go run ./.submodules/nostos/cmd/nostos node install tp4
About to install tp4 (method=tpi). Pass --yes to skip prompt.
✗ provisioner: preflight failed: tpi: no image_digest pinned for
  3616c4c8.../v1.10.3/arm64; refusing to fetch on first run

The original v0.2 spec required strict pinning: see openspec/changes/nostos-v02-provisioners/specs/tpi-provisioning/spec.md, scenario “Missing digest fails closed.” No cluster.image_digests entry meant Preflight refused to download.

Step 2 — Trade strict pinning for TOFU

Strict-pin forced the operator to manually SHA-256 the factory image before the first install. Relaxed to TOFU (trust-on-first-use): when no digest is pinned, the first download is recorded into ~/.cache/nostos/digests.json; subsequent runs verify against that recorded value. A Preflight WARN tells the operator they are in TOFU mode.

Code: internal/provisioner/tpi/tpi.go (Preflight) and internal/provisioner/tpi/image_cache.go (imageCache.Ensure, readRecordedDigest, writeRecordedDigest).

$ nostos node install tp4
→ tpi preflight: TCP turingpi.local:443 ok
⚠ no image_digest pinned for 3616.../v1.10.3/arm64; trusting TLS
   to factory.talos.dev (TOFU)
→ fetching Talos image
▼ downloading metal-arm64.raw.xz (123 MiB)
→ recorded sha256:e3b0c44... for 3616.../v1.10.3/arm64

Step 3 — “Device not configured” from tpi flash

✗ tpi flash: exit status 1: stderr: open /dev/...: device not configured

Misleading error from the tpi CLI. Real cause: BMC required HTTP-basic auth. The provider read TPI_USERNAME / TPI_PASSWORD from the child env but the 1Password fields were empty. Filed as Bug #6.

Step 4 — BMC creds added in 1Password

Created op://kubernetes/home-systems/TURING_BMC_USERNAME and TURING_BMC_PASSWORD in 1Password, referenced from nostos/config.yaml:

tp4:
  boot:
    method: tpi
    tpi:
      host: turingpi.local
      slot: 4
      username_ref: op://kubernetes/home-systems/TURING_BMC_USERNAME
      password_ref: op://kubernetes/home-systems/TURING_BMC_PASSWORD

Rerun output (preflight → fetch → flash):

$ nostos node install tp4
→ tpi preflight ok
→ image ready: ~/.cache/nostos/images/3616.../v1.10.3/metal-arm64.raw
→ tpi power off -n 4 ... (already off; non-fatal)
→ tpi flash -i metal-arm64.raw -n 4
  Writing 1.8 GiB ........................ 100%
→ tpi power on -n 4

The resolved password is set via Cmd.Env only; argv contains exclusively non-secret paths and flags. See Boot in internal/provisioner/tpi/tpi.go.

Step 5 — UART shows old kernel after flash

tpi uart -n 4 reported the same kernel version as before the flash. Talos was apparently not booting from the freshly written eMMC.

Root cause: the cluster default schematic (4a0d65c6..., used for the Dell amd64 controlplane) did not include the siderolabs/sbc-rockchip overlay. Without it the arm64 metal image lacks the Rockchip device-tree bits required to boot RK3588.

Step 6 — Per-node schematic_id override

Added SchematicID as a per-node override and an EffectiveSchematic(cluster) helper. tpi.Prepare calls it when computing image URL + digest key. See internal/config/config.go (Node.SchematicID, Node.EffectiveSchematic).

tp1:
  arch: arm64
  schematic_id: 3616c4c824f2540c0a14da0cc8e6fc46143f2ca0cc75c9c6376a66e562894950
  boot:
    method: tpi
    tpi: { host: turingpi.local, slot: 1, ... }

With the rockchip-overlay schematic, the next flash booted to maintenance mode.

Step 7 — WaitMaintenance timeout (Bug #1)

✗ provisioner: timeout: tpi wait maintenance: context deadline exceeded

Default WaitMaintenanceDeadline was 10 minutes. RK1 cold-boot from flash to apid-on-50000 was clocking >14 minutes on this lab. The orchestrator gave up while the node was still booting. (Now defaulted to 20 min, see InstallOpts.withDefaults in internal/cluster/orchestrate.go.)

Step 8 — Manual talosctl apply-config --insecure as workaround

$ talosctl --insecure -n 192.168.68.114 apply-config \
    --file nostos/state/configs/tp4.yaml

Worked because Step 9 had landed the fname=name fix to registry.Render. Until that fix, the rendered file landed at configs/.yaml.

Step 9 — Empty filename for tpi nodes (Bug #2) FIXED

registry.Render derived the filename from node.MACHyphen(). tpi nodes have no MAC — their network is the BMC — so MACHyphen returned "", and two tpi nodes overwrote each other on disk at nostos/state/configs/.yaml.

Fix in this session, internal/registry/registry.go:

fname := node.MACHyphen()
if fname == "" {
    fname = name   // fall back to node name for tpi/non-PXE nodes
}
out := p.Configs() + "/" + fname + ".yaml"

Step 10 — ext-tailscale crash loop after install

$ kubectl -n kube-system logs ext-tailscale-tp1 -p
panic: tailscale: authkey rejected (used or expired)

The op://kubernetes/talos/TAILSCALE_AUTH_KEY ref pointed at a static authkey that had been consumed by a previous install. Each fresh install re-rendered the same dead key into the machineconfig and the Talos extension entered CrashLoopBackOff.

Step 11 — Tailscale OAuth-mint backend

Replaced the static authkey ref with a new tailscale://authkey URI scheme backed by Tailscale's OAuth client_credentials grant. Each render mints a fresh, single-use, ephemeral, preauthorized auth key via POST /api/v2/tailnet/-/keys and embeds it into the machineconfig.

Code lives in internal/secrets/tailscale.go (TailscaleBackend, fetchAccessToken, mintKey, ListKeys, RevokeKey). Wired into the secrets registry in internal/secrets/factory.go when secrets.tailscale is configured.

secrets:
  tailscale:
    oauth_client_id_ref:     op://kubernetes/talos/tailscale-oauth-client-id
    oauth_client_secret_ref: op://kubernetes/talos/tailscale-oauth-client-secret
    tags: [tag:k8s]
    expiry: 7776000
    preauthorized: true
    description: nostos

Templates reference it as a URI, not a literal:

extensions:
  tailscale:
    authKey: tailscale://authkey

Step 12 — Tailscale ACL update for tag:k8s

Minting a key with capability tags: [tag:k8s] requires the OAuth client to be permitted to issue keys carrying that tag. Updated the tailnet ACL tagOwners stanza accordingly. Verification: nostos secrets test tailscale mints + revokes a probe key successfully.

3. Architecture walkthrough

v0.2 lands eight new packages, refactors three existing ones, and threads a single set of seams (Commander, Clock, Secrets) through every provider. This section walks each package: what it does, where it lives, why it exists (citing design.md decisions D1–D5), and how it composes with the rest.

3.1 internal/provisioner/ — the interface and the registry

File: .submodules/nostos/internal/provisioner/provisioner.go (~125 lines).

Defines four exported types and one registry:

  • Phase — enum string. Constants: preflight, prepare, boot, wait, apply, bootstrap, ready, error, cleanup. The orchestrator emits a phase marker on transition; events carry phase, kind, message, and a clock-supplied timestamp.
  • Event{Phase, Kind, Message, At} — superseded the v0.1 free-form (kind, message) tuple after critic 2.1 pointed out the run-log scenario was unsatisfiable without phase. EventEmitter is a function alias func(Event).
  • Provisioner interface — the seven methods listed below. Method() + ContentionKey() are pure; the five lifecycle hooks are (ctx, *config.Node, EventEmitter) error (with Apply additionally taking configPath).
  • Deps{Cfg, Paths, Secrets, Cmd, Clock} — the bag of seams every provider receives at construction time. Cmd is the subprocess seam (execx.Commander); Clock is the time seam (clockx.Clock); Secrets is a marker interface widened in v0.3.
  • Registry: package globals regMu, registry map[string]Factory, plus Register(method, Factory), New(method, Deps) (Provisioner, error), Methods(). Register panics on empty/duplicate; New returns ErrNotRegistered for unknown methods.

Why: design D1. The interface decouples “how does this hardware reach Talos maintenance mode” from the orchestrator. Adding redfish/proxmox/usb/rpi-imager in later releases is purely a matter of importing a new package whose init() calls provisioner.Register. cmd/nostos/main.go blank-imports providers it ships.

The Provisioner contract (verbatim from provisioner.go)

type Provisioner interface {
    Method() string
    ContentionKey(node *config.Node) string

    Preflight(ctx, node, emit) error
    Prepare(ctx, node, emit) error
    Boot(ctx, node, emit) error
    WaitMaintenance(ctx, node, emit) error
    Apply(ctx, node, configPath string, emit) error
    Cleanup(ctx, node, emit) error
}

Hook idempotency contract (from glossary in design.md):

PreflightNo observable side effect. Safe to re-run.
PrepareConverges to same on-disk state. Cache hits short-circuit.
BootNOT idempotent: tpi flash is destructive every run. Re-entry guarded by per-node flock + live-node reinstall guard.
WaitMaintenancePure poll. Safe to re-run.
ApplyProvider-documented. PXE no-op trivially safe; tpi apply-config -i succeeds once per maintenance window.
CleanupIdempotent. Safe to call twice.

3.2 internal/provisioner/errors.go — sentinel errors

File: internal/provisioner/errors.go. Six sentinel errors, all matched via errors.Is:

SentinelReturned when
ErrPreflightAny Preflight failure that should abort before side effects.
ErrBootBoot-phase failure (e.g. tpi flash non-zero exit).
ErrTimeoutA hook's deadline expired.
ErrLockedPer-node flock contended (EWOULDBLOCK).
ErrNodeAlreadyReadyLive-node reinstall guard: target node is healthy and --reinstall was not passed.
ErrNotRegisteredUnknown method passed to provisioner.New.

3.3 internal/provisioner/pxe/ — rehomed PXE flow

File: internal/provisioner/pxe/pxe.go (~245 lines).

Wraps the v0.1 internal/pxe/ server behind the new interface. Behavior preserved bit-for-bit for dell01.

  • Method() = "pxe"; ContentionKey(_) = "pxe:server" (only one dnsmasq+:9080 binding can exist).
  • Preflight calls pxe.NewServer(p.deps.Paths).Preflight() — detects ethernet interface, port :9080 free, dnsmasq binary present.
  • Prepare queues a one-shot wipe (cluster.QueueWipe against pending-wipes.json) unless SkipWipe is set, builds PXE assets via pxeserver.BuildAll, and re-renders boot.ipxe with talos.experimental.wipe=system when wipe is active.
  • Boot calls srv.Start(serveCtx, ni) against a context the provider owns (cancelled in Cleanup), then spawns the HTTP-request tap goroutine that emits download events for kernel/initramfs and config-fetched when Talos pulls its rendered machineconfig.
  • WaitMaintenance waits for either ctx-done or the tap goroutine ending; PXE delivers the config in-band so this is effectively a wait-for-tap rather than a poll.
  • Apply is a no-op. The orchestrator never invokes talosctl apply-config -i for PXE because the iPXE chain already delivered the config. This was the single biggest correction from the critic review (D2 / critic 3.2): symmetry-for-its-own-sake would have caused a double-apply race.
  • Cleanup stops the server, joins the tap goroutine (2-second deadline), consumes the wipe queue on success, and re-renders boot.ipxe back to a clean (no-wipe) form.
  • Exposes SetSkipWipe(bool) and SetServeTimeout(d) setters honored by the orchestrator via type-assertion (InstallOpts.SkipWipe / ServeTimeout).

Why: design D3 “pxe (refactor only).” The dell01 install must produce the same observable event-Kind subsequence as v0.1 — asserted by a topological subsequence test, not a byte-equal golden.

3.4 internal/provisioner/tpi/ — Turing Pi BMC provider

File: internal/provisioner/tpi/tpi.go (~360 lines). Image cache split into image_cache.go (~210 lines).

Replaces taskfiles/turing.yml end to end. Highlights:

  • Method() = "tpi"; ContentionKey(node) = "tpi:<host>" — every slot on a Turing Pi shares one BMC.
  • Preflight verifies: tpi --version ≥ 1.0.0 (regex-parsed), TCP host:443 connect within 2s (mockable via dialTimeout seam), every credential _ref resolves through the secrets backend, and (TOFU branch) emits a WARN if no digest is pinned for this (schematic, version, arch).
  • Prepare hands off to imageCache.Ensure (next subsection) and returns the path to the decompressed .raw.
  • Boot materializes the optional identity-file ref to a 0600 file inside a 0700 per-run dir at ~/.cache/nostos/secrets/<run-id>/tpi-key (with O_CREAT|O_EXCL and an lstat-based symlink refusal), populates TPI_USERNAME/TPI_PASSWORD on the child env, and runs three subprocesses through p.deps.Cmd: tpi --host <h> power off -n <slot> (“already off” substring is non-fatal), tpi --host <h> flash -i <raw> -n <slot>, tpi --host <h> power on -n <slot>. Stdout passes through runStream + coalesce with a 200ms window before reaching emit().
  • WaitMaintenance polls talosctl --insecure -n <ip> version every 5s using p.deps.Clock.NewTimer. Returns when the version response parses; returns ErrTimeout wrapping ctx.Err() on deadline.
  • Apply runs talosctl apply-config -i -n <ip> --file <configPath>. The path is the orchestrator's 0600 temp file under ~/.cache/nostos/secrets/<run-id>/; the orchestrator unlinks it after Apply returns.
  • Cleanup: if bootErr is set, best-effort tpi power off -n <slot> with the fresh 60s context; always remove the materialized identity-file and the parent secrets dir.

3.5 internal/provisioner/tpi/image_cache.go — sha256-pinned + TOFU

  • Image URL: https://factory.talos.dev/image/<schematic>/<version>/metal-<arch>.raw.xz. Base URL is a package-level var so tests can swap in httptest.Server.
  • Cache root: ~/.cache/nostos/images/<schematic>/<version>/ (mode 0700). Cache files mode 0600. cacheDirFn is a seam.
  • imageCache.Ensure(ctx): on cache hit and digest match, returns the existing .raw path immediately. On cache miss or digest drift, deletes stale files, downloads to a .part sibling, sha256s it, atomic-renames to the canonical name, decompresses to .raw using github.com/ulikunitz/xz (Go-native, no shell-out per security §8).
  • Pin source priority: (1) cluster.image_digests["<schematic>/<version>/<arch>"]; (2) recorded TOFU digest at ~/.cache/nostos/digests.json; (3) on first run with neither, the observed digest is recorded post-download.
  • Mismatch behavior: file unlinked, typed error returned with both expected and actual hashes. No retry in v0.2.

Why: design D3 (“Image integrity”) and security §7. The original spec required strict pinning; relaxing to TOFU is a session-level decision (see Bug #5 for the race window TOFU introduces).

3.6 internal/provisioner/redact/ — secret scrubber

File: internal/provisioner/redact/scrubber.go. Two exported APIs:

  • Scrubber: holds a slice of secret strings, sorted longest-first to make overlapping prefixes redact correctly. AddAll([]string), Scrub(string) string. Marker is the literal [REDACTED].
  • WrapEmitter(EventEmitter, *Scrubber) EventEmitter — returns a wrapped emitter whose every Event.Message passes through Scrub. nil next is replaced by a no-op; nil scrubber returns next unchanged.

Why: security §6 and critic 1.2. Provider discretion is not part of the redaction story — the orchestrator wraps the emitter once with a Scrubber seeded with the resolved-secret table for the run; every provider emit and every captured child stdout/stderr passes through it.

3.7 internal/provisioner/contention/ — keyed mutex

File: internal/provisioner/contention/map.go. Implements an in-process keyed mutex:

  • Map.Acquire(key) func() blocks until the lock for key is held; returns a release closure (idempotent). Empty keys return a no-op release immediately.
  • Internal entry{mu, ref} is refcounted so map keys are GC'd when the last release fires.
  • Process-wide contention.Default + free-function contention.Acquire(key) for callers.

Why: design D4. Two installs whose providers return the same non-empty key serialize at the Apply boundary; distinct keys parallelize. tpi:<host> serializes slots on a board; pxe:server serializes PXE-server installs; an empty key means “no contention.”

3.8 internal/provisioner/flock/ — per-node OS file lock

File: internal/provisioner/flock/node.go. Cross-process safety. Production callers use AcquireNodeAt(p.Configs(), name):

  • Opens nostos/state/configs/<name>.lock mode 0600.
  • Calls unix.Flock(fd, LOCK_EX|LOCK_NB).
  • On EWOULDBLOCK returns fmt.Errorf("%w: lockfile %s held by another process", ErrLocked, path).
  • Release closure unlocks + closes; idempotent.

Why: security §9 + design D5. Two nostos node install <name> invocations from the same workstation must not race the apply-config window. Cross-host concurrent operators are explicitly out of scope (documented as a gap).

3.9 internal/provisioner/provisionertest/ — compliance suite

File: internal/provisioner/provisionertest/compliance.go. Exposes RunComplianceSuite(t, factory). Both the pxe and tpi providers wire it (pxe/compliance_test.go, tpi/compliance_test.go). Invariants:

  • Method() stable across calls and non-empty.
  • ContentionKey() pure (same input → same output).
  • Cleanup idempotent under a fresh context.Background.

Why: tests review §1 + tasks 1.8. Land seams in PR #1 before any provider migration.

3.10 internal/execx/ — Commander interface

File: internal/execx/commander.go.

type Commander interface {
    Run(ctx, name string, args, env []string,
        stdin io.Reader, stdout, stderr io.Writer) error
}
type OSCommander struct{}
func (OSCommander) Run(...) { exec.CommandContext(...).Run() }

Every provider's subprocess spawn goes through p.deps.Cmd. Tests inject a FakeCommander that records argv, env, stdin and serves scripted stdout/exit. Production wires execx.OSCommander{} in cluster.Install. Why: design D-Tests + tests §2. grep -R 'exec\.Command' internal/provisioner returns zero hits.

3.11 internal/clockx/ — Clock interface

File: internal/clockx/clock.go. Clock{Now, Sleep, NewTimer} + Timer{C, Stop, Reset} + Real implementation. Tests inject a FakeClock so deadline / coalescing tests are deterministic. Why: design D-Tests; grep -R 'time\.Now\|time\.Sleep' internal/provisioner hits only emit* helpers in the pxe provider where event timestamps need wall time — deliberately scoped.

3.12 internal/secrets/tailscale.go — OAuth-mint backend

File: internal/secrets/tailscale.go (~430 lines). Implements the tailscale:// URI scheme on the existing secrets backend interface.

  • Scheme() = "tailscale". Only resource shape supported is tailscale://authkey with optional query overrides (?tags=tag:k8s&expiry=3600&reusable=false&ephemeral=true&preauthorized=true&description=...).
  • Validate(): hits the OAuth token endpoint to confirm client_id+client_secret resolve and the auth_keys scope grants — without minting a key. Surfaced by nostos secrets list and nostos secrets test.
  • Resolve(uri): mints a fresh key per call. The OAuth access token is fetched per Resolve (no caching) so the blast-radius of a leaked token is limited to one render. See fetchAccessToken.
  • MintKey(ctx, opts) / ListKeys(ctx) / RevokeKey(ctx, id) for CLI use cases (secrets test, secrets keys list, secrets keys revoke).
  • redactToken(s) scrubs anything matching tskey-(auth|api|client)-... from error messages so leaks via wrapped errors / %v are caught.
  • Refs are resolved through a chained RefResolverFunc built in secrets.BuildBackends: the Tailscale backend never knows about op:// / file:// / sops:// directly — it asks the resolver, the resolver dispatches by scheme.

3.13 internal/cluster/orchestrate.go — refactored Install pipeline

File: internal/cluster/orchestrate.go (~280 lines). The post-refactor Install shape:

1.  acquire flock(p.Configs(), nodeName)            // ErrLocked if held
2.  prov, _  = provisioner.New(method, deps)        // {pxe, tpi}
3.  prov.Preflight(ctx, &node, emit)
4.  if !opts.Reinstall && probeReady(node) {        // talosctl version
        return ErrNodeAlreadyReady
    }
5.  configPath, cleanupTmp = renderToTemp(...)      // 0600 in 0700 dir
6.  defer prov.Cleanup(freshCtx60s, &node, emit)
7.  release = contention.Acquire(prov.ContentionKey(&node))
8.  prov.Prepare(ctx, &node, emit)
9.  prov.Boot(ctx, &node, emit)
10. prov.WaitMaintenance(waitCtx, &node, emit)      // ctx + deadline
11. prov.Apply(ctx, &node, configPath, emit)
12. release()                                       // free contention
13. probeApid loop                                  // 3 min
14. if controlplane: Bootstrap + FetchKubeconfig
15. emit Kind=ready

Notable contracts:

  • The raw events channel is wrapped with redact.WrapEmitter(bridge, scrub) before any provider sees it. Provider emits flow through Scrubber.
  • renderToTemp renders the canonical config (preserving v0.1 layout) then copies into a fresh nostos-secrets-XXXX tempdir at mode 0700, file at 0600.
  • runCleanup derives its context from context.Background with a 60s timeout, surviving Ctrl-C of the run context.
  • contention.Acquire spans Boot–Apply with a guarded releaseKeyOnce closure that the deferred Cleanup also drops if it ran early.

3.14 internal/config/config.go — schema additions

File: internal/config/config.go. Additions vs v0.1:

  • Boot{Method string, TPI *TPIBoot} on Node. Method enum: {pxe, tpi}. Default pxe when block omitted.
  • TPIBoot{Host, Slot, UsernameRef, PasswordRef, IdentityFileRef}.
  • Ref typed string with custom UnmarshalYAML. Allows op://, sops://, file://; explicitly rejects env:// with a typed error; rejects everything else.
  • Cluster.ImageDigests map[string]string with key <schematic>/<version>/<arch>.
  • Node.SchematicID per-node override + Node.EffectiveSchematic(cluster) resolver.
  • Secrets.Tailscale *TailscaleConfig: optional block enabling the tailscale:// scheme.
  • Validator: (host, slot) uniqueness across all tpi-method nodes; PXE method requires MAC; tpi method does not (its network is the BMC).

3.15 internal/cli/{node_install,secrets,commands}.go

Files: internal/cli/node_install.go (~65 lines), internal/cli/secrets.go (~225 lines), internal/cli/commands.go (~245 lines, mostly v0.1 carry-over).

  • nostos node install NAME is the canonical entry. It blank-imports both provisioner/pxe and provisioner/tpi so their init() registrations fire.
  • nostos up remains as a deprecated alias (commands.go, newUpCmd) printing deprecated: nostos up; use 'nostos node install <name>' on stderr.
  • nostos secrets list / secrets test [scheme] / secrets keys list / secrets keys revoke: secrets-introspection surface added in this session for the Tailscale OAuth flow.

4. Architecture decisions

Each decision below is grounded in openspec/changes/nostos-v02-provisioners/design.md (D1–D5, D-Open, D-Tests) and the four parallel reviews. “Alternatives” list what was considered and rejected; “Tradeoff” names what we lose; “Cite” points at the source of truth.

D1. Provisioner interface vs. switch statement

Decision. A Go interface (Provisioner) with seven methods plus a registry keyed by method string. The orchestrator holds zero method-specific code paths.

Alternatives. (a) switch node.Boot.Method { case "pxe": ...; case "tpi": ... } in the orchestrator. (b) A NodeView value type passed to providers to decouple them from internal/config.

Tradeoff. Each new provider must wire seven methods even when most are trivial (PXE's Apply is a no-op). NodeView would have meant maintaining two parallel field sets; rejected per critic 2.4 — providers import internal/config read-only.

Cite. design.md D1; specs/provisioner/spec.md “Provisioner interface decouples install method from orchestrator.”

D2. Apply is provider-owned (PXE no-op, tpi runs talosctl)

Decision. Each provisioner declares its own delivery semantics in Apply. PXE returns nil immediately because the iPXE chain delivered the rendered config in-band. tpi runs talosctl apply-config -i --file <configPath> out-of-band.

Alternatives. Symmetry-for-its-own-sake: the orchestrator always invokes talosctl apply-config -i after WaitMaintenance. Critic 3.2 + security §4 demonstrated this would double-apply on the LAN for PXE — racing the maintenance-mode close window and breaking “no external behavior change for dell01.”

Tradeoff. The interface contract is mildly asymmetric (Apply behavior depends on the provider), but the test asserts “FakeCommander records zero talosctl apply-config -i calls during PXE install” and “exactly one during tpi install” — the assertion would have been impossible with forced uniformity.

Cite. design.md D2; specs/provisioner/spec.md “Provisioner Apply hook owns config delivery.”

D3. Cleanup runs in a deferred block with a fresh context

Decision. Cleanup is invoked in a defer block whose ctx is derived from context.Background() with a 60-second deadline, not from the run context. See runCleanup in internal/cluster/orchestrate.go.

Alternatives. Honor the parent ctx cancellation in Cleanup. Adopted briefly until critic 2.3 + tests §1 surfaced: a Ctrl-C during WaitMaintenance would propagate into Cleanup, abort the tpi power off, and leave the slot in an indeterminate power state — the exact failure mode the spec claims to prevent.

Tradeoff. Cleanup may run for up to 60s after the operator pressed Ctrl-C. Operators expect a hard kill via second Ctrl-C to bypass.

Cite. design.md D2; specs/provisioner/spec.md “Cleanup runs on every termination path with a fresh context.”

D4. ContentionKey vs. BMCKey

Decision. The interface method is ContentionKey(node) string. PXE returns "pxe:server"; tpi returns "tpi:<host>"; an empty string means “no shared resource.”

Alternatives. BMCKey() (the planner draft). Rejected because PXE-server contention is structurally identical (one process can bind dnsmasq+:9080 at a time) and the orchestrator should not have a special-case lock for PXE alongside the per-provider key.

Tradeoff. The name is one word longer.

Cite. synthesis.md “Interface contracts — ContentionKey replaces BMCKey”; specs/provisioner/spec.md “ContentionKey serializes shared-resource installs.”

D5. flock at OS level vs. in-process mutex

Decision. Per-node lock at nostos/state/configs/<name>.lock via unix.Flock(LOCK_EX|LOCK_NB), held from the top of Install until return.

Alternatives. Rely on the in-process contention.Map only. Rejected because two nostos node install tp1 shells from the same workstation would race the apply-config window with destructive side effects — see security §9.

Tradeoff. Cross-host operators (two laptops) are still unprotected; documented as a gap. flock is POSIX-only; Windows would require a different implementation when/if it becomes a target.

Cite. design.md D4; specs/provisioner/spec.md “Per-node flock serializes concurrent local invocations.”

D6. Render after Preflight (no secrets touch disk before cheap checks)

Decision. The orchestrator calls Preflight first, then renderToTemp (which resolves op:// / tailscale:// refs and writes a 0600 file). Render runs after Preflight, after live-node guard, before Prepare.

Alternatives. Render-first (the planner draft). Rejected per critic 3.1: a Preflight failure after Render leaves a stale config on disk containing freshly resolved secrets.

Tradeoff. Preflight cannot validate machineconfig syntax (which would require rendering); accepted in v0.2.

Cite. design.md D2 “Key contracts — render after Preflight”.

D7. Image digest TOFU vs. strict pin

Decision. Pinned digest in cluster.image_digests wins. If absent, fall back to TOFU: first download is recorded into ~/.cache/nostos/digests.json; subsequent runs verify against the recorded value. A WARN is emitted in TOFU mode.

Alternatives. Strict pin only (the planner spec). Operationally too strict for first-time setup of a new SBC overlay; the operator has no way to know the digest before the first download.

Tradeoff. First download trusts TLS to factory.talos.dev. Documented as Bug #5 (TOFU race window).

Cite. Session decision; revises specs/tpi-provisioning/spec.md “Missing digest fails closed.”

D8. Per-node schematic_id override vs. cluster-only

Decision. Add Node.SchematicID to override Cluster.SchematicID per-node. Resolution centralized in Node.EffectiveSchematic(cluster Cluster) string.

Alternatives. One schematic per cluster. Rejected the moment we tried to flash an arm64 RK1 module with the amd64-Dell schematic and the rockchip overlay was missing. Heterogeneous fleets are the real-world case.

Tradeoff. Image cache fans out by schematic, so multiple SBC families on one workstation each occupy ~1.8 GiB of decompressed .raw.

Cite. Session decision; internal/config/config.go (Node.SchematicID, EffectiveSchematic).

D9. Tailscale OAuth-mint vs. static authkey

Decision. A new tailscale://authkey URI scheme backed by Tailscale's OAuth client_credentials grant. Each render mints a fresh, single-use, ephemeral, preauthorized key.

Alternatives. Static op:// ref, manually rotated by the operator before each install. Rejected after the live crash loop (timeline Step 10) and per security §3 — single-use semantics are silently broken on retry.

Tradeoff. Adds a runtime dependency on the Tailscale API. Failed mints during render abort the install before any flash; this is the right failure mode.

Cite. Session decision; internal/secrets/tailscale.go.

D10. Fresh OAuth token per Resolve vs. cache-with-TTL

Decision. fetchAccessToken runs once per Resolve call. No caching across calls.

Alternatives. Cache the token for its full expires_in (~1h). Rejected: a single render is at most a handful of mints, the OAuth endpoint is fast, and a leaked cached token has a wider blast radius than a fresh one used immediately.

Tradeoff. Slightly more API traffic; negligible at lab scale.

Cite. internal/secrets/tailscale.go (Resolve: “The backend never caches the OAuth access token across Resolve calls”).

D11. Subprocess secrets via env, not argv

Decision. Resolved BMC creds reach the tpi child via TPI_USERNAME/TPI_PASSWORD on cmd.Env. Argv contains only non-secret paths and flags. Identity-file refs materialize to a 0600 file inside a 0700 dir; only the path appears in argv.

Alternatives. argv concatenation (tpi --user $u --password $p). Rejected per security §2/§8: argv is visible via ps, /proc/<pid>/cmdline, and many shell-history loggers.

Tradeoff. If a future tpi version drops env support and only takes argv, we'd have to use stdin or fail loudly. The Preflight version pin (≥ 1.0.0) anchors us against that drift.

Cite. design.md D7; specs/tpi-provisioning/spec.md “BMC credentials use _ref typed schema and never reach argv or events.”

D12. 60s Cleanup timeout (fresh context) vs. honor parent ctx

Decision. Cleanup gets a fresh context.Background-derived 60s context. Survives Ctrl-C of the run. Single try — no retry, no backoff in v0.2.

Alternatives. 30s (planner draft) — too short for flaky BMCs (critic 2.3). Multiple retries — deferred to v0.3 once we have telemetry on real flash latencies.

Tradeoff. Open question (D-Open Q2): if real flashes show >60s power-off latency we raise it. v0.2 ships single-try.

Cite. design.md D-Open Q2.

5. CLI reference

Every command shipped or modified in v0.2. Synopsis, what happens under the hood, sample output, when to use, when not to use.

nostos node install NAME [--reinstall] [--yes]

Synopsis. The canonical install entry. Method-dispatched: looks up cfg.Nodes[NAME].Boot.Method and constructs the registered provisioner.

Step by step (internal/cli/node_install.go → internal/cluster/orchestrate.go Install):

  1. Load nostos/config.yaml; look up the node by name.
  2. Print the confirmation banner (“About to install name (method=method). Pass --yes to skip prompt.”) unless --yes.
  3. Wire signal.NotifyContext for SIGINT/SIGTERM.
  4. Spawn an events goroutine. Every cluster.Event is rendered with a colored prefix icon (→ progress, ▼ download, ✓ ready, ✗ error).
  5. Inside Install: flock node, build provisioner, Preflight, live-node guard, render to temp, register Cleanup defer, contention.Acquire, Prepare, Boot, WaitMaintenance, Apply, probe apid, optional Bootstrap+FetchKubeconfig (controlplane), emit ready.

Sample (tpi).

$ nostos node install tp1 --yes
→ starting install of tp1
→ tpi preflight ok
→ fetching Talos image
→ image ready: ~/.cache/nostos/images/3616.../v1.10.3/metal-arm64.raw
→ tpi --host turingpi.local power off -n 1
→ tpi --host turingpi.local flash -i metal-arm64.raw -n 1
→ tpi --host turingpi.local power on -n 1
→ waiting for apid
◉ apid up on tp1
✓ tp1 is Ready. kubeconfig: nostos/state/kubeconfig

Use when you want a fresh install of a node from config.yaml.

Do NOT use when the node is already a healthy cluster member — the live-node reinstall guard refuses with ErrNodeAlreadyReady unless --reinstall is passed; even then, expect destructive flash on tpi nodes. Pair --reinstall with --yes only after explicit operator confirmation.

nostos node list

Synopsis. Print all nodes registered in config.yaml, sorted by name. Reads cfg.Nodes via registry.List.

Sample.

$ nostos node list
NAME    ROLE          ARCH   IP               METHOD  TEMPLATE

Use when auditing which nodes the workstation knows about. Do NOT use as ground truth for cluster membership — use kubectl get nodes for that.

nostos render NAME

Synopsis. Render NAME's template into nostos/state/configs/<mac-or-name>.yaml. Resolves op://, file://, sops://, tailscale:// refs in the process.

Step by step (internal/registry/registry.go Render):

  1. Read template at nostos/templates/<Node.Template>.
  2. Build backends via secrets.BuildBackends(cfg).
  3. Run secrets.ResolveTemplate(body, backends): every URI of the form scheme://... is resolved by its registered backend.
  4. Filename: node.MACHyphen() if non-empty, else NAME (the Bug #2 fix).
  5. Write 0600. If talosctl is on PATH, run talosctl validate --mode metal.

Use when debugging a template, comparing the resolved output, or feeding a manual talosctl apply-config recovery.

Do NOT use as a substitute for node install — a render alone does not boot, flash, or apply anything; it just resolves secrets and writes a file. Be aware: minted Tailscale auth keys are spent the moment the file is rendered, even if you never apply it.

nostos status

Synopsis. For every node in config.yaml, probe ICMP + TCP:50000, optionally fetch talosctl version. Prints a compact table.

Implemented via registry.Probe (internal/registry/registry.go): pings, dials TCP:50000 (apid), and runs talosctl version --short when apid is up.

Sample.

$ nostos status
NAME    PING  APID  VERSION
dell01  up    up    v1.10.3
tp1     up    up    v1.10.3
tp4     up    up    v1.10.3

Use when sanity-checking the lab. Do NOT use when relying on “healthy in K8s” — apid up only means Talos is reachable; for K8s readiness see kubectl get nodes.

nostos secrets list

Synopsis. List the schemes registered in the secrets registry and their Validate() status (PASS/FAIL).

For each backend (op, file, env, tailscale) calls Validate(). The Tailscale backend's Validate hits the OAuth token endpoint without minting.

$ nostos secrets list
SCHEME       STATUS  DETAIL
env          PASS    ok
file         PASS    ok
op           PASS    ok
tailscale    PASS    ok

Use when verifying the workstation can reach all secret backends before an install run.

nostos secrets test [scheme]

Synopsis. Like list, but for the tailscale backend it actively mints a 60-second probe key and revokes it. Without arguments it tests all schemes.

$ nostos secrets test tailscale
tailscale    PASS  minted+revoked smoke key id=k123abc

Use when first wiring up the OAuth client — confirms the scope (auth_keys) and tagOwners ACL allow minting with your configured tags.

Do NOT use on a tight ACL where every minted key shows up in audit log noise; the smoke key is short-lived but it still hits the audit log.

nostos secrets keys list

Synopsis. Inventory of all auth keys in the configured tailnet (per the OAuth client's view). Hits GET /api/v2/tailnet/-/keys and enriches each with a per-key GET so capabilities/expiry are accurate.

$ nostos secrets keys list
ID        DESCRIPTION  EXPIRES               USED  TAGS
k123abc   nostos       2026-08-23T00:00:00Z  false  tag:k8s
k456def   nostos       2026-08-23T00:00:00Z  true   tag:k8s

Use when tracking authkey debt: which keys this OAuth client has minted, which are spent, which still live.

nostos secrets keys revoke KEY_ID

Synopsis. DELETE /api/v2/tailnet/-/keys/<id>. Returns Revoked <id> on success.

Use when a node is decommissioned and you want to retire its (single-use already-spent) authkey from the audit log.

nostos up NAME deprecated

Synopsis. Thin alias for nostos node install NAME retained for v0.2 compatibility. Prints deprecated: nostos up; use 'nostos node install <name>' on stderr and proceeds through the same code path.

Slated for removal in v0.3 (per design D-Open Q4: 90-day grace period from v0.3 release).

Do NOT use in new scripts. Update Taskfile recipes to task nostos:install NODE=<name>.

7. Per-node template guide

Each node references a Talos machineconfig template under nostos/templates/<name>.yaml. Templates are plain Talos YAML (version: v1alpha1) with embedded URI references. The render pipeline replaces every URI of the form scheme://... with the value its registered backend resolves.

Supported URI schemes

SchemeBackendResolution
op://<vault>/<item>/<field>1PasswordShells out to op read with --account set from secrets.onepassword.account.
sops://<path>SOPSDecrypts via age key file from secrets.sops.age_key_file.
file://<path>fileReads file at path; trims trailing newline.
tailscale://authkey[?...]Tailscale OAuthMints fresh auth key; query params override defaults from secrets.tailscale.
env://<NAME>envReads os.Getenv(NAME). Rejected at unmarshal for Ref-typed fields (BMC creds).

Example fragments

Talos machine token (every node) — plain op:// ref:

machine:
  type: worker
  token: op://kubernetes/talos/MACHINE_TOKEN
  ca:
    crt: op://kubernetes/talos/MACHINE_CA_CRT
    key: ""

Tailscale extension (any node that should join the tailnet):

# Talos system extension config
- name: ext-tailscale
  configFiles:
    - content: |
        AUTHKEY=tailscale://authkey
        TS_EXTRA_ARGS=--accept-routes --accept-dns=false
      mountPath: /var/etc/tailscale/tailscaled.env

Each nostos render <name> mints a fresh ephemeral key. Caveat: the key is spent at render time; if the run aborts before the node consumes it, the key dies unused. Operators reviewing keys via nostos secrets keys list see them for their full TTL.

Rendering pipeline

Implemented in internal/secrets/template.go (ResolveTemplate):

  1. Scan the template body for tokens of the form scheme://... respecting word boundaries.
  2. For each match, look up the backend by scheme; if unknown, fail loud (“no backend registered for ref ...”).
  3. Call backend.Resolve(uri); on success replace; on failure surface the wrapped error with the URI for fast operator triage.
  4. The orchestrator then writes the resolved bytes to a 0600 temp file (path goes to talosctl apply-config -i --file).

Template authoring rules

  • Never inline a literal credential. The Ref typed field for BMC creds enforces this at unmarshal time, but the rest of the template is plain YAML — reviewers should grep for password: / token: with non-URI values.
  • Per-node hostnames, install disks, IP/MAC, hardware-specific kernel args belong in the template, not in config.yaml.
  • For RK1 nodes the template typically pins install.image to the same factory image used to flash, plus the rockchip extensions; nostos/templates/tp1.yaml is the reference example.
  • For dell01 the controlplane bootstrap PKI is included; that template additionally references op://kubernetes/talos/MACHINE_CA_KEY.

9. Bugs found this session

Bug #1 — BootTimeout < RK1 boot time open

Symptom. WaitMaintenance returns ErrTimeout while the RK1 is still mid-boot. Empirically RK1 cold-boot from flash to apid-on-50000 takes 12–18 minutes on this lab (eMMC + Rockchip firmware + Talos kernel/initramfs decompression).

Status. Mitigated by raising InstallOpts.WaitMaintenanceDeadline default to 20 minutes (internal/cluster/orchestrate.go). Not a fix — a fix would key the deadline off arch + disk type + schematic. Tracked as v0.3 work.

Operator workaround. Pass a longer deadline via --wait-deadline (when wired in v0.3) or rerun after manual talosctl --insecure version confirms apid is up.

Bug #2 — Empty filename for tpi nodes FIXED

Symptom. registry.Render wrote tpi-node configs to nostos/state/configs/.yaml. Two tpi nodes overwrote each other; manual recovery via talosctl apply-config --file read the wrong content.

Cause. Filename was always node.MACHyphen(). tpi nodes have no MAC; MACHyphen returned an empty string.

Fix. Fall back to the node name when MAC is empty. Landed in this session in internal/registry/registry.go:

fname := node.MACHyphen()
if fname == "" {
    fname = name
}

Bug #3 — --host turingpi.local redundancy cosmetic

Symptom. tpi flash --host turingpi.local -i ... -n 1 works, but the same workstation also has the host pre-configured in ~/.config/tpi.toml; passing --host on every call is redundant noise in the audit log.

Status. Not fixed. The provider always passes --host for determinism (multiple Turing Pi boards in a lab is a real future case). Cost: an extra noisy argv per call. Tracked for v0.3 (“maybe omit when only one board is configured”).

Bug #4 — Render command tree inconsistency cosmetic

Symptom. nostos render NAME exists at the top level (legacy), while nostos node install, nostos node list, etc. live under node. There is no nostos node render.

Status. Not fixed. Adding node render as an alias is a one-line change but it would risk encouraging operators to render-without-installing, which spends Tailscale auth keys for no reason. Holding for v0.3 with a clearer warning.

Bug #5 — Image digest TOFU race (record after, not before) design tradeoff

Symptom. In TOFU mode, the workstation downloads a fresh image, sha256s it, and records the digest. If two install runs interleave (one operator, two shells, two distinct nodes that share a schematic), both compute their own digest before either records; the slower writer overwrites the faster.

Status. Not fixed in v0.2. Race window is small (one HTTP fetch). Mitigation: the recorded digest is verified on every subsequent run; if drift is observed, the file is re-downloaded. The flock ensures one nostos invocation per node, but not per schematic.

Proper fix (v0.3). Per-schematic flock on the digest store, or move the digest record into the same atomic-rename as the cached .raw.xz.

Bug #6 — tpi “Device not configured” misleading error upstream

Symptom. tpi flash exits 1 with stderr open /dev/...: device not configured when the BMC rejects HTTP-basic auth. The error message has no relation to authentication; operators reach for tpi --help and lose 30 minutes.

Cause. Upstream tpi CLI: BMC returns 401, tpi tries to open a device file as a fallback path, that fails with the misleading kernel error.

Workaround. nostos's Preflight resolves and validates BMC creds before invoking tpi. If the operator points at a 1Password ref that doesn't exist, the secrets backend surfaces a precise error long before tpi flash runs. The remaining failure mode (creds resolve, BMC rejects them) is rare in practice.

12. The four parallel reviews

Before implementation, the v0.2 spec was put through four independent reviews captured at v0.2/review-{critic,security,analyst,tests}.md. Each lens caught a distinct class of issue. Synthesis lives at v0.2/synthesis.md.

Critic (architecture & scope)

Top finding. The proposal locked in v0.3/v0.4/v1.0 shape while claiming a smallest-slice posture: six-method enum, JSONL run log, inventory.db schema, doctor catalog. Each pre-committed v0.3 work to v0.2 review.

Sharpest call. D2's “unified ApplyConfigInsecure” would double-apply on the LAN for PXE — “no external behavior change for dell01” was directly in tension with the orchestrator reshape.

Adopted. Method enum cut to {pxe, tpi}. Apply became provider-owned (no-op for PXE, talosctl for tpi). NodeView dropped — providers consume *config.Node. JSONL log + inventory.db moved to v0.3.

Security

Top finding. Redaction was prose, not a runtime control. Image SHA-256 source of truth was hand-waved. Tailscale authkey lifecycle was missing entirely.

Adopted. Scrubber implemented as a wrapper around the EventEmitter, seeded once per run. cluster.image_digests map added (operator-pinned, git-auditable; TOFU was a session-time relaxation). identity_file_ref materialization spec'd (0600 in 0700 dir, O_CREAT|O_EXCL, lstat rejects symlinks). Ref typed string with custom YAML unmarshaller replaces the “credential-shaped value” heuristic. Per-node flock added. Subprocess secrets via env, never argv. Tailscale OAuth-mint backend (Step 11 in the timeline) is the v0.2-time response to security §3's “missing authkey lifecycle” — spec required single-use TTL, this session went one further and automated it.

Analyst (requirements engineering)

Top finding. Load-bearing terms were undefined: “RK1” (RK1 vs Turing-Pi-hosted module class), “Ready” (apid? bootstrap? joined to etcd?), “maintenance mode” (TCP listen vs apid-on-50000 with parseable response), “drift,” “idempotent.” Spec scenarios that asserted “kind=ready” were satisfiable by emitting a literal string with no observable system state.

Adopted. Definitions section in design.md (RK1, maintenance mode, Ready, boot method, ContentionKey, in-band vs out-of-band). WaitMaintenance success requires parseable talosctl --insecure version response, not TCP-listen. “Ready” defined per-role (worker = apid up; controlplane = + etcd healthy + kubeconfig fetched). Method enum cut closes the “BMC overloaded across iLO/iDRAC/Turing Pi/Proxmox” ambiguity.

Tests

Top finding. The proposal had ~24 acceptance signals, a third of which were string matches against event kinds and a third “manual evidence in PR.” The change is testable iff three seams — Commander, Secrets, Clock — land in PR #1 before any provider migration.

Adopted. Seams shipped first: internal/execx/Commander, internal/clockx/Clock, the existing internal/secrets Resolver. Compliance suite at internal/provisioner/provisionertest/. Subsequence-based regression for dell01's PXE install (no byte-equal goldens). Property test for redaction (∀ string, secret table, no member appears as substring after Scrub). FakeClock for the 200ms coalescing window's emit-count ceiling. grep-level invariants: grep -R 'time\.Now\|time\.Sleep' internal/provisioner tightly scoped; grep -R 'exec\.Command' internal/provisioner zero hits.

How synthesis combined them

The synthesis pass cut six items, tightened nine interface contracts, replaced eleven hand-waved acceptance signals with concrete observables, and recorded five open questions in design.md D-Open. The four reviews disagreed in places (critic wanted three hooks, tests wanted five-plus-Cleanup); synthesis kept five hooks because the tpi provider needs distinct Prepare/Boot/WaitMaintenance/Apply phases and merging them obscures the cleanup ordering.
