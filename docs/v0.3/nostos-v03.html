nostos v0.3 — Dashboard, AI-CLI & Hygiene

Companion to v0.2. Sources: openspec/changes/nostos-v03-dashboard-and-hygiene/, docs/nostos-guide.md, .submodules/nostos/AGENTS.md, and the v0.3 review synthesis. Generated 2026-05-25.

v0.2 shipped the Provisioner abstraction; v0.3 closes its operational gaps and turns the CLI into something an agent can drive. Headline deliverables: four production bug fixes, a read-only Bubble Tea dashboard, a JSON contract on every command, an embedded operator guide, and a deliberately retired taskfiles/turing.yml.

  • 4 v0.2 bugs closed — BootTimeout per-provisioner, image-cache TOFU two-phase commit, BMC pre-flight with typed errors, regression test for the empty-filename fix.
  • AI-friendly CLI — --output json on every command, nostos schema, --fields, --dry-run with zero subprocess invocations, structured errors in the 10–15 exit-code range, control-char + path-traversal hardening.
  • Read-only dashboard MVP — discovery, 5 aggregate states, fast/slow refresh tiers, headless --once, embedded living docs for dell-optiplex-3080m and turing-rk1. Action dispatch (r/d/i) deferred to v0.4.
  • Operator guide at docs/nostos-guide.md — install + recover + reference; per-vendor playbooks and OAuth deep-dive deferred to v0.4.
Streams: A B1–B3 C1–C7 D E1–E4 206 tests / 18+ packages B4 / C8 / dashboard actions → v0.4 No new provisioners (Redfish/Proxmox/USB stay separate)

4.2 Five aggregate states

StateTriggerTop-bar imperative
ALL_GREENevery probe in every tier passes—
DEGRADED≥1 non-fatal probe failed (e.g. upstream patch available)"Press G to open the upgrade preview."
BROKEN≥1 fatal probe failed (k8s api, kubelet NotReady, etcd unhealthy)"Press G to open the recovery section for: …"
UNCONFIGUREDzero nodes in config.yaml4-step CTA replaces the body — never green
TRANSITIONINGany per-node flock held (install in flight from another shell)"Hold; install in progress."

Why UNCONFIGURED is its own state: a green bar on a zero-node cluster is technically true but useless. The CTA is the opinionated alternative.

4.3 Refresh tiers

Two tiers — both run synchronously inside the Bubble Tea event loop, no separate goroutine pool:

  • fast (5 s) — ICMP, Talos apid, Tailscale presence, k8s API. Anything cheap.
  • slow (5 min) — schematic-vs-running diff, Talos upstream-release diff (factory.talos.dev), Helm chart vs OCI registry HEAD, ArgoCD application sync state.

Upstream diffs are cached at ~/.cache/nostos/upstream-versions.json (24 h TTL). Cold start hydrates from cache, then refreshes in the background. BMC pre-flight is not on either tier — it runs only inside node install or explicit nostos node check (security review §A3).

5. AI-friendly CLI surface

v0.3 puts every nostos subcommand through the eight principles from the ai-friendly-cli skill. The result is a CLI that an agent can plan against, dry-run, and parse without screen-scraping lipgloss output.

--output json & NDJSON C1

Every command that prints prose today gains --output json. List operations stream NDJSON (one JSON object per line) so an agent can consume incrementally without buffering. Default remains text for humans; setting NOSTOS_OUTPUT=json in the environment flips the default per-shell. Errors in JSON mode print to stdout (so an agent reading one stream sees them); errors in text mode go to stderr.

nostos schema C2

Reflection-driven schema introspection. With no argument it emits the full command tree (flags, args, types, required, enum, description) as JSON. With an argument it emits a single command's schema; with --exit-codes it dumps the typed exit-code catalogue. The dashboard's ? help is not auto-generated from this — help is curated prose — but agents and shell completion machinery share one source of truth.

--fields token-cost discipline C3

Field masks on every command that emits JSON: --fields=id,ip,role. Unknown identifiers fail with E_FIELDS_UNKNOWN; empty entries (a,,b) fail with E_FIELDS_EMPTY; control chars in the mask fail with E_FIELDS_CONTROL. Designed so an agent can constrain its own context-window footprint without parsing the full payload first.

--dry-run with zero subprocess invocations C4

Every mutation (node install, secrets keys revoke, future cluster upgrade) accepts --dry-run. Contract per the tests review: zero os/exec calls, output JSON contains would_execute: [...], and re-running without --dry-run produces an execution sequence that is a (sub)sequence of would_execute. Exit code on dry-run is 0 with payload status:"preview" — there is deliberately no dedicated dry-run exit code.

Structured errors + exit codes C5

Errors are JSON objects: {error, code, message, details} where code is an E_* identifier (E_NODE_NAME_CONTROL, E_BMC_UNREACHABLE, etc.) and details is a free-form bag (e.g. {host:"…", port:443}). Exit codes use the 10–15 range so they don't collide with shell idioms (1 stays "generic"):

CodeCategory
0success
1internal_error (un-classified bug)
10validation_failed
11network_error
12auth_error
13conflict
14not_found
15timeout

BMC-specific failures from the tpi provider (ErrBMCUnreachable, ErrBMCAuth, ErrBMCVersion) map onto these categories and carry sub-causes in details.code rather than burning unique top-level numbers. Eliminates the v0.2 review's exit-code-8 collision concern.

Input hardening C6

internal/cli/inputx/ rejects all ASCII control characters (0x00–0x1F + 0x7F) in any user-supplied string, not just node names. Path validation rejects .. after lex-clean and any path that resolves outside $HOME or the repo root after symlink resolution. op:// refs cannot carry query strings or fragments. YAML inputs whose anchors resolve to filesystem paths are rejected. Four FuzzNodeName / FuzzOpRef / FuzzConfigPath / FuzzFieldMask targets at a 5 s budget each guard the contract.

6. MCP server deferred to v0.4

Stream C8 (Model Context Protocol) is deferred to v0.4. The v0.3 contract is the JSON CLI; v0.4 wraps it as JSON-RPC 2.0 over stdio. The shape below is documented now so the operator guide §9.5 ships with concrete examples and so v0.4 can implement against a stable surface.

6.1 Protocol summary

  • Transport: stdio, JSON-RPC 2.0, framed by newlines.
  • Tool naming: one tool per cobra command — nostos.<method-id>. Single source of truth: cobra → schema → MCP.
  • Input schema: derived from cobra flags via internal/cli/schema. No second schema to keep in sync.
  • Return shape: identical to nostos <cmd> --output json.

7. Bug fixes (the v0.2 backlog)

Each card lists the symptom observed during the v0.2 session, the root cause, and the v0.3 fix. Sources: v0.2 session log + openspec/changes/nostos-v03-dashboard-and-hygiene/proposal.md §"Concrete pains".

#1 — BootTimeout too short for RK1 fixed

Symptom: orchestrator gives up after 10 min; operator falls back to manual talosctl apply-config --insecure, defeating the point.

Root cause: internal/cluster/orchestrate.go:64-65 hard-coded a 10-min default; RK1 cold boots routinely take 12–18 min.

Fix (A1): add Provisioner.MaxWaitMaintenance() time.Duration (default 0). tpi returns 30 min, pxe returns 0 (orchestrator's 20 min stands). Orchestrator uses max(opts.WaitMaintenanceDeadline, prov.MaxWaitMaintenance()); per-flag --wait-deadline still wins.

#5 — Image-cache TOFU race fixed

Symptom: kill -9 mid-download leaves a partial file; on the next run there's a chance the corrupt digest gets recorded as canonical.

Root cause: internal/provisioner/tpi/image_cache.go:27-39 recorded the digest in digests.json after trusting the on-disk file. No two-phase commit.

Fix (A2): stream-hash on download into a *.part file → Close+Rename → fsync → then write the digest record, all in one critical section. Temp files at startup are garbage; deleted unconditionally (no resume-from-*.part heuristic — would re-introduce a TOCTOU between byte-count and hash). Cache-hit path recomputes sha256 before trusting any record; mismatched record → delete file and redownload.

#6 — BMC unreachable surfaces as os error 6 fixed

Symptom: wrong/unreachable BMC shows up as "Device not configured (os error 6)" from the tpi subprocess. Operators waste 20+ minutes chasing kernel-level red herrings.

Root cause: tpi binary's stderr is unfiltered; nostos passed it through verbatim.

Fix (A3): BMC pre-flight at internal/provisioner/tpi/bmc_preflight.go. TCP host:443 probe → HTTP GET / with auth → typed errors ErrBMCUnreachable / ErrBMCAuth / ErrBMCVersion. Probes are scoped strictly to the configured BMC host (no internal-IP discovery, no /24 walking). Token-bucket rate-limit: at most one probe per host per 5 s; failure backoff 5 s → 30 s → 5 min.

#2 — Empty filename regression fixed

Symptom: in v0.2, tpi-rendered configs occasionally produced an empty filename (.yaml) under nostos/state/configs/. Patched late in v0.2 with no pinned regression test.

Root cause: the rename path used node.MAC when the tpi flow had not yet populated it from the BMC response.

Fix (A4): regression test that loads nodes[tp1], runs a render with a stub BMC response, and asserts the output filename is non-empty and contains the node identifier. Test lives in internal/provisioner/tpi/render_test.go.

10. The four parallel reviews

Before implementation, the v0.3 proposal was put through four independent reviews. Each review's headline finding folded into the synthesis at v0.3/synthesis.md and modified the OpenSpec change.

Critic review — kill the autopilot framing

The headline draft pitched a guided-fix dispatcher as the north star. The critic flagged that this contradicts every Non-Goal in the same document: no autopilot, no Tailscale cleaner, no cluster upgrade mutation, no MCP. Reframed as "live status board, not autopilot". Same review collapsed the 4-tier refresh cadence (200 ms / 5 s / 30 s / 5 m) to two tiers, dropped the cold-start snapshot cache as theatre, picked hardcoded over the "plugin-ready" check registry seam, and cut vendor playbooks for hardware not in the lab.

Security review — TOFU, BMC scoping, and tailnet spoofing

Made the image-cache two-phase commit explicit: temp file → atomic rename → digest record + fsync in the same critical section. Removed the resume-from-*.part heuristic (would introduce a TOCTOU between byte-count and hash). Scoped BMC pre-flight strictly to the configured host (no /24 walking — that's a LAN-scanning fingerprint) with token-bucket rate-limiting. Killed Stream B4 (Tailscale device cleanup) for v0.3: the OAuth-backed DELETE path is exploitable for tailnet spoofing if an attacker can force a delete of a still-trusted device. v0.4 ships nostos cluster cleanup with explicit allow-listing + two-keystroke confirm.

UX review — five states, contextual footer, capital chords

Three aggregate states became five: explicit UNCONFIGURED with a 4-step CTA (never green on a zero-node config) and explicit TRANSITIONING (a single offline worker mid-reflash should not read as BROKEN). Symbols are colorblind-safe (✓ ⚠ ✗ ? + bracket variants under NO_COLOR=1). Capital H/G avoid collision with potential lower-case actions. Footer is contextual by selected row type. ? help is curated prose, decoupled from nostos schema output.

Tests review — --dry-run contract and exit-code 8 collision

Tightened --dry-run to a property: zero subprocess invocations, JSON output contains would_execute: [...], and re-running without --dry-run produces an execution sequence that is a (sub)sequence of would_execute. Exit code on dry-run is 0 with payload status:"preview" — no dedicated dry-run exit code. Eliminated the v0.2 review's exit-code 8 collision by collapsing the catalogue to six entries in the 10–15 range and pushing sub-causes (BMC unreachable vs auth vs version, digest mismatch vs unpinned) into details.code. Added the missing-kubeconfig and empty-cluster behaviours as explicit, documented, tested branches rather than silent skips.

11. Roadmap — v0.4 and beyond

11.1 v0.4 (next)

  • Dashboard action dispatch — r reinstall, d delete, i identify (Redfish chassis-LED → NIC packet flood → tpi UART, in that order — most visually unambiguous first).
  • Guided-fix dispatcher — capital G moves from "open the guide section" to "execute the recommended remediation" with a two-keystroke confirm.
  • Stream B4 — nostos cluster cleanup — Tailscale offline device pruning behind explicit allow-listing + tagged-namespace + two-keystroke confirm.
  • Stream C8 — MCP server — JSON-RPC 2.0 over stdio, one tool per cobra command, schema derived from the v0.3 schema registry.
  • cluster upgrade --to <ver> — mutation behind the same dispatch seam (v0.3 ships preview only).
  • secrets rotate — Tailscale authkey rotation.
  • nostos doctor — pre-flight all the things; sibling to secrets test.
  • Operator-guide §5/§6 — per-vendor playbooks (generic-amd64, raspberry-pi-5) + Tailscale OAuth deep-dive.

11.2 v0.5+ deferred

  • Plugin / pluggable check registry (v0.4 first redesigns with concrete use cases).
  • JSONL run log + --resume for interrupted installs.
  • inventory.db (SQLite) for historical state.
  • Drift detection + nostos diff <node>.
  • New provisioners: redfish, proxmox, usb, rpi-imager — each on its own openspec change.

11.3 v1.0 (unchanged from v0.2 plan)

  • Stable CLI surface (no breaking changes).
  • Vendored iPXE binary.
  • Homebrew + container distribution.
  • Hardware test matrix (6+ vendor playbooks).
